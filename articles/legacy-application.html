Working with Legacy Applications

Memahami, memperbaiki dan menjaga aplikasi lama tetap hidup

Legacy application adalah sesuatu yang sangat familiar bagi banyak software engineer yang bekerja di dunia enterprise.

Aplikasi tersebut mungkin sudah berumur 5, 10, bahkan lebih dari 15 tahun. Tetapi aplikasi tersebut masih digunakan setiap hari karena masih menjalankan proses bisnis yang penting.

Dari pengalaman saya, bekerja dengan legacy application membutuhkan pendekatan yang berbeda dibandingkan membuat aplikasi baru.

Apa Itu Legacy Application?

Secara sederhana, legacy application adalah aplikasi lama yang masih digunakan dan masih memiliki nilai bagi organisasi.

Legacy tidak selalu berarti aplikasi tersebut buruk.

Bisa saja aplikasinya stabil, cepat, dan sudah memahami kebutuhan bisnis selama bertahun-tahun.

Masalah Terbesar Bukan Selalu Source Code

Ketika pertama kali menangani aplikasi lama, developer sering langsung fokus pada source code.

Padahal ada hal yang jauh lebih penting:

  • Business process
  • Database structure
  • Relationship antar tabel
  • Integrasi dengan sistem lain
  • Server environment
  • Configuration
  • Dependency
  • Kebiasaan user

Tanpa memahami hal tersebut, perubahan kecil pada aplikasi lama bisa menyebabkan masalah besar.

Dokumentasi Sering Menjadi Masalah

Salah satu tantangan legacy system adalah dokumentasi yang tidak lengkap.

Developer yang membuat aplikasi mungkin sudah pindah, struktur organisasi berubah, dan orang yang sekarang melakukan maintenance harus memahami sistem dari nol.

Source code akhirnya menjadi salah satu dokumentasi terpenting.

Database Adalah Bagian Penting dari Legacy System

Dalam banyak aplikasi bisnis lama, business logic tidak hanya berada di source code.

Sebagian logic bisa berada di:

  • Stored Procedure
  • Trigger
  • View
  • Function
  • Job
  • Database constraint

Karena itu memahami database menjadi sangat penting ketika melakukan maintenance aplikasi lama.

Jangan Langsung Rewrite

Salah satu keputusan yang sering terdengar mudah adalah:

"Aplikasi ini sudah tua. Kita rewrite saja."

Tetapi rewrite sebuah sistem enterprise bukan pekerjaan kecil.

Kita harus memahami seluruh proses bisnis sebelum mengganti sistem lama.

Jika tidak, aplikasi baru mungkin terlihat lebih modern tetapi justru kehilangan beberapa proses penting yang sebelumnya sudah berjalan dengan baik.

Stabilitas Kadang Lebih Penting daripada Teknologi Baru

Dalam dunia bisnis, aplikasi bukan dinilai hanya dari seberapa modern teknologi yang digunakan.

Yang lebih penting adalah:

  • Apakah aplikasi stabil?
  • Apakah data aman?
  • Apakah proses bisnis berjalan?
  • Apakah user dapat bekerja?
  • Apakah sistem dapat dipelihara?

Teknologi terbaru belum tentu menjadi solusi terbaik untuk semua kondisi.

Troubleshooting Legacy Application

Ketika aplikasi lama mengalami masalah, saya biasanya mencoba membaginya menjadi beberapa bagian. 

Application
     |
     +---- UI
     |
     +---- Business Logic
     |
     +---- Database
     |
     +---- Network
     |
     +---- Operating System
     |
     +---- Hardware

Dengan membagi masalah seperti ini, proses troubleshooting menjadi lebih terarah.

Jangan Mengubah Terlalu Banyak Sekaligus

Ketika memperbaiki aplikasi lama, perubahan kecil biasanya lebih aman.

Ubah satu bagian, test, lalu lihat hasilnya.

Jika kita mengubah banyak bagian sekaligus dan kemudian muncul error, akan lebih sulit menentukan perubahan mana yang menyebabkan masalah.

Legacy System Membutuhkan Kesabaran

Ada kalanya kita menemukan source code yang sulit dipahami, nama variable yang tidak jelas, query yang panjang, atau struktur database yang sudah sangat kompleks.

Reaksi pertama mungkin ingin menulis ulang semuanya.

Tetapi sering kali solusi terbaik adalah memahami sistem tersebut sedikit demi sedikit.

AI dan Legacy Application

Saat ini AI juga mulai membantu pekerjaan dengan legacy application.

AI dapat membantu menjelaskan source code lama, membuat dokumentasi, mencari kemungkinan bug, atau membantu memahami query yang kompleks.

Tetapi hasil AI tetap harus diperiksa.

AI tidak mengetahui seluruh business process perusahaan hanya dari beberapa potongan source code.

Developer tetap harus menjadi orang yang memahami konteks sistem.

Skill yang Dibutuhkan

Menurut pengalaman saya, developer yang bekerja dengan legacy application membutuhkan beberapa kemampuan:

  • Programming
  • Database
  • Debugging
  • Problem solving
  • Business process analysis
  • System analysis
  • Communication dengan user
  • Patience

Legacy Tidak Selalu Berarti Buruk

Ada sistem lama yang justru sangat stabil karena telah melewati berbagai macam kondisi selama bertahun-tahun.

Sistem tersebut telah diuji oleh penggunaan nyata, bukan hanya oleh developer dan tester.

Karena itu saya percaya bahwa legacy application seharusnya tidak langsung dianggap sebagai sesuatu yang harus dibuang.

Kesimpulan

Bekerja dengan legacy application memberikan pengalaman yang berbeda dari sekadar membuat aplikasi baru.

Kita belajar memahami sistem yang sudah ada, menghargai business process, membaca database, melakukan troubleshooting dan membuat perubahan dengan risiko seminimal mungkin.

Jangan hanya bertanya bagaimana cara mengganti aplikasi lama. Tanyakan terlebih dahulu mengapa aplikasi tersebut masih dibutuhkan.

Karena mungkin masalahnya bukan pada teknologinya, tetapi pada bagaimana kita memahami sistem tersebut.
